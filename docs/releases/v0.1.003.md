# vcpkg-cache v0.1.003 — paired Lemon host tools

This infrastructure source/Action/CMake release adds the host Lemon parser
generator and its matching **lempar.c** template. It contains
[PR #273](https://github.com/qigao/vcpkg-cache/pull/273); existing `v0.1.002`
and `v0.1.0` tags stay unchanged.

## Published tool package

`Qigao.Lemon.Binary` **1.0.0** contains native Linux, macOS and Windows x64/ARM64
executables, paired templates and per-host source/binary/template hash manifests.
The source pair is SQLite 3.54.0 commit
`6932c59ee5c280599dfae9e7b431698a7cab9687`, pinned by SHA-256.
Windows uses llvm-mingw, Unix runner-native Clang; Linux x64 is built on
Ubuntu 22.04 for its glibc floor.

The attached nupkg, `lemon.lock.json` and `SHA256SUMS` are the exact artifacts
qualified by all packed readers and published with SHA-256 readback through
curl. The source publisher does not create this Release until that succeeds.
No Mono, dotnet/NuGet executable, product SDK or native vcpkg ABI publication
is involved.

## Downstream CMake

Use a full infrastructure checkout with `ref: v0.1.003`, and the attached lock:

```cmake
include("${VCPKG_INFRA_ROOT}/cmake/QigaoLemon.cmake")
qigao_setup_lemon(
  LOCK_FILE "${CMAKE_SOURCE_DIR}/cmake/lemon.lock.json"
  HOST_RID "${MY_BUILD_HOST_RID}")
# Exports Lemon::Lemon, LEMON_EXECUTABLE and LEMPAR.
```

The RID is the **build host** even when targeting Android or another architecture.
Pass `Lemon::Lemon` and `${LEMPAR}` to the existing downstream
`cmake_add_grammar`, or use the imported executable in a custom command and
depend on both the tool and template.

The generic `setup-native-dependency@v0.1.003` Action can restore the same lock
with `payload: tools/<host-rid>`, the required template and host executable.
For offline/public-release downloads, supply the attached nupkg using
`ARCHIVE_FILE` in CMake or `--archive` in the CLI; the lock hash and package
identity are still checked before extraction. See
[complete Lemon usage](../../packaging/lemon/README.md).

Infrastructure version `v0.1.003`, Lemon package version `1.0.0`, SQLite source
version `3.54.0` and vcpkg ABI hashes are independent identities. Git registry
`reference` uses this tag; its `baseline` must use the actual full commit
resolved from `v0.1.003`, not the version string.

## Validation

The exact approved PR HEAD must pass the existing curl and cache-contract
workflows and the Lemon package workflow. Lemon qualification builds six native
hosts and runs seven packed-reader environments (including Ubuntu 22.04 and
24.04): CMake restores the exact package, imports its host tool, generates and
compiles a C11 parser, and executes precedence/parentheses/invalid-input tests.
The source publisher verifies matching merged source and reuses the original
qualified master publication run, whose exact bytes were read back after upload.
It checks that run's six builds, seven packed readers and successful publication,
then repeats remote SHA-256 verification before attaching those same artifacts
and creating the new immutable-name source tag. It never rebuilds an archive
under the already-published Lemon 1.0.0 version.

SaltsUtils' 12 real grammars also generated without diagnostics in the read-only
compatibility check. Its actual source migration and full parser/IDL runtime
tests remain a separate downstream change.
